# Custom MCP Servers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a user add their own MCP servers (name, URL, optional API key) and have those tools available to the Telegram agent, reusing the generic MCP client already built for Swiggy.

**Architecture:** New DB table + CRUD routes in `apps/backend`, a new dependency and an extended `loadMCPTools()` in `packages/agent-core`'s `ConnectorRegistry`, a new UI section in `packages/ui-connectors` wired into `apps/landing`'s dashboard. Along the way, fixes a pre-existing gap this feature depends on: `loadMCPTools()` is never actually called in production today.

**Tech Stack:** Drizzle ORM (Postgres/Neon), Hono, TypeScript, Bun test, React (inline styles, no CSS framework — matches the rest of `ui-connectors`).

## Global Constraints

- Full design rationale and rejected alternatives (auto-OAuth-detection
  explicitly out of scope for v1) live in
  `docs/superpowers/specs/2026-07-21-custom-mcp-servers-design.md` — read
  it if anything here seems underspecified.
- Auth mode: `Authorization: Bearer <key>` when an API key is provided, no
  auth header when empty. Never imply auto-OAuth-detection in UI copy.
- MCP server URLs must be `https://` only — the URL carries the user's API
  key in every request header, so plaintext `http://` would leak it.
- A broken custom server must never break the built-in MCP-def loading
  path (currently only Swiggy), or another of the user's own custom
  servers — each server connects independently, failures are caught and
  logged, never thrown further.
- Deploying code does not run the DB migration — `bun run db:migrate`
  (from `packages/db`) must be run against the live DB manually after
  merge, per this project's established convention.
- No React component test harness in `ui-connectors` or `apps/landing` —
  UI tasks are verified with typecheck + lint only, consistent with every
  other UI feature this session.

Create `apps/backend/src/routes/custom-mcp.ts`:

```ts
import { Hono } from "hono"
import { eq, and } from "drizzle-orm"
import { db, customMcpServers } from "@yomi/db"
import { authenticate } from "../auth.js"
import { encryptString } from "../services/token-encryption.js"

export function validateCustomMcpServerInput(input: {
  name?: string
  url?: string
}): string | null {
  if (!input.name?.trim() || !input.url?.trim()) return "name and url are required"
  let parsed: URL
  try {
    parsed = new URL(input.url)
  } catch {
    return "url must be a valid URL"
  }
  if (parsed.protocol !== "https:") return "url must use https"
  return null
}

export function isDuplicateUrlError(err: unknown): boolean {
  return String(err).includes("custom_mcp_servers_user_url_unique")
}

export const customMcpRouter = new Hono()

customMcpRouter.get("/", authenticate, async (c) => {
  const userId = c.get("user").id
  const rows = await db
    .select({ id: customMcpServers.id, name: customMcpServers.name, url: customMcpServers.url })
    .from(customMcpServers)
    .where(eq(customMcpServers.userId, userId))
  return c.json({ servers: rows })
})

customMcpRouter.post("/", authenticate, async (c) => {
  const userId = c.get("user").id
  const body = (await c.req.json()) as { name?: string; url?: string; apiKey?: string }
  const validationError = validateCustomMcpServerInput(body)
  if (validationError) return c.json({ error: validationError }, 400)

  try {
    const [row] = await db
      .insert(customMcpServers)
      .values({
        userId,
        name: body.name!.trim(),
        url: body.url!.trim(),
        apiKeyEncrypted: body.apiKey?.trim() ? encryptString(body.apiKey.trim()) : null,
      })
      .returning({
        id: customMcpServers.id,
        name: customMcpServers.name,
        url: customMcpServers.url,
      })
    return c.json({ server: row }, 201)
  } catch (err) {
    if (isDuplicateUrlError(err)) {
      return c.json({ error: "You've already added a server with this URL" }, 409)
    }
    throw err
  }
})

customMcpRouter.delete("/:id", authenticate, async (c) => {
  const userId = c.get("user").id
  const id = c.req.param("id")
  await db
    .delete(customMcpServers)
    .where(and(eq(customMcpServers.id, id), eq(customMcpServers.userId, userId)))
  return c.json({ ok: true })
})
```

    if (this.userId && this.mcpConnectedIds.length > 0 && Object.keys(this.mcpTools).length === 0) {
      for (const baseDef of ALL_CONNECTOR_DEFS) {

              getAccessToken: this.deps.getAccessToken,
              createPendingAction: this.deps.createPendingAction,
            })
            Object.assign(this.mcpTools, tools)
          } catch (err) {
            console.error(`[registry] MCP connect failed for ${def.id}:`, err)
          }
